# 경기 남부 공급·멸실 — 공표 통계가 없는 것을 직접 센다

공급 분석 탭의 경기 남부 숫자가 어디서 오는가. 공표 공급 표는 시도까지만 오므로
K-apt 전수·KOSIS 시군구 CSV·건축물대장 전수로 메우고, 멸실은 해마다 뜨는 스냅샷으로
직접 관측한다. 탭이 그 숫자를 어떻게 보여 주는지는 [공급 분석](../analysis/supply.md),
공표 통계 일반은 [공표 통계](reb.md) 에 있다.

## 왜 공표 통계로 못 내나

"경기 공급량이 북부도 포함이냐" 는 물음에 표를 다시 뒤졌다. **공급 표에는 시 단위
분류가 하나도 없다.**

| 표 | 경기 관련 분류 | 그중 시 단위 |
|---|---|---|
| 준공 | 20개 | 0개 |
| 착공 | 20개 | 0개 |
| 인허가 | 9개 | 0개 |
| 가구수 · 멸실 | 각 1개 | 0개 |

전부 `경기>총계`, `경기>공공부문>소계` 같은 **성격별** 분류지 지역별이 아니다.
**미분양만 예외**로 시 단위가 있다.

얼마나 다른지는 그 미분양에서 보인다. 잰 날(2026-10) 경기 전체 미분양이 14,509호인데
경기 남부 8개 시는 **834호**였다. 17배 차이다 — 경기 전체를 남부로 읽으면 안 된다는
근거가 수치로 나온다.

## K-apt 전수 집계

공급량 자체는 **K-apt 의무관리대상 공동주택**을 17개 구 전수로 받아 메운다.
`ingest_kapt` 와 다르다 — 그쪽은 우리 단지에 세대수를 **붙이느라** 이름이 정확히
맞는 것만 쓰고, 이쪽은 **붙이지 않고** 통째로 담는다(`ingest_kapt_all`). 공급량을
세는 데는 매칭이 필요 없다. 처음 받았을 때 1,945곳, 목록 9초 · 단지별 기본정보
11~26분이었다.

**이것은 '준공' 이 아니다.** 이름을 똑바로 붙여야 한다.

- 의무관리대상만 — 소규모 단지·빌라·단독이 빠진다
- **지금 존재하는 단지만** — 철거된 단지가 없어 과거일수록 과소집계된다
- 아파트만 — R-ONE 의 주택 준공(주택 전체)과 **직접 뺄 수 없다**

그래서 적정 공급(가구 증가+멸실)에서 이 값을 빼지 않는다. 빼서 '경기 남부 부족분'
을 내면 그럴듯한 거짓이 된다. **추세만 견준다.**

최근 두 해는 사용승인이 아직 안 난 단지가 있어 덜 찬 값이다. 막대를 흐리게 그리고
`partial_from` 으로 어느 해부터인지 알려 준다 — 똑같이 그리면 '최근 급감' 으로
읽힌다.

## 가구 증가 — 손으로 받은 CSV 로

적정 공급의 분모(가구 증가)는 경기도기본통계 `DT_21002I001`(주택 현황 및 보급률)에
**시군구별로** 있다. API 가 없어 사람이 내려받는다. 원자료와 메타자료를
`backend/data/manual/` 에 날짜를 박아 함께 둔다 — 다시 받을 수 없으면 재현할 수 없다.
받는 법과 파일 설명은 그 폴더의 `README.md` 에 있다.

**적재할 때마다 대조한다.** 경기 합계 일반가구수를 우리가 이미 가진 R-ONE
`households`(시도)와 맞춰 본다. 처음 적재한 2021~2024 네 해 모두 **차이 0.00%** 였다.
같은 통계를 시군구까지 내린 것이 맞다. 어긋나면 종료 코드 1 — 다른 표를 받아 왔다는
뜻이다.

쓸 수 있는 구간은 **2021년부터다.**

- 2015~2020 은 시군구 값이 전부 `-` 다(경기 합계만 있다)
- 2008년에 일반가구수 **정의가 바뀐다**(우리 8개 시 합이 +246,344 로 튄다)
- 2021년에 주택수 **출처가 바뀐다**(경기도 주택정책과 → 주택총조사). 메타자료가
  "20년까지의 계산값과는 다를 수 있음" 이라고 적어 두었다

**시군구 주택보급률은 쓰지 않는다.** 공표값이 `...` 로 비어 있고, 주택수÷가구수로
직접 만들면 경기 합계가 88.7% 가 되는데 공표값은 99.4% 다(11%p). 보급률은 국토교통부
**추계자료**이고 다가구주택을 구분거처로 세기 때문이다. 직접 나눈 값을 '보급률' 이라고
띄우면 공표 통계와 어긋난 숫자를 사실처럼 보여 주는 셈이 된다.

**빼지 않는다.** 가구 증가는 모든 주택 유형의 수요이고 K-apt 입주는 아파트만이라
1:1 로 맞물리지 않는다. 나란히 두고 사람이 견주게 한다.

### 두 자료가 서로를 검산한다

같은 CSV 의 아파트 재고로 K-apt 집계를 맞춰 봤다.

| | 값 |
|---|---|
| 아파트 재고 증가 (2021→2024, 주택총조사) | +122,111호 |
| K-apt 입주 합 (2022~2024, 사용승인) | 130,485세대 |
| 차이 | **6.9%** |

기관도 방식도 다른 두 자료가 이만큼 맞으면 K-apt 집계를 믿을 근거가 된다. 남는
차이는 멸실분과 연말 기준 시차로 설명된다. 이 검산은 화면의 창에도 적는다 —
**검산했다는 사실 자체가 숫자의 일부**다.

## 멸실은 공표되지 않는다 — 직접 관측한다

세 곳을 다 뒤졌고 셋 다 **시도 단위**였다.

| 어디 | 어떻게 확인했나 | 결과 |
|---|---|---|
| 한국부동산원 R-ONE | 표 738개 재훑기 | 멸실 표 1개, 분류 20개 — 시군구 0 |
| KOSIS | '멸실' 통합검색 | 통계표 10건 중 실제 멸실은 1건 |
| 국토교통 통계누리 | 뷰어의 내부 JSON 직접 호출 | **20행 = 전국·수도권·지방 + 시도 17개** |

마지막 것이 결정적이다. `/portal/stat/data.do?formId=5416` 을 열어 보면 지역이
`전국·수도권·지방·서울·부산·…·경기·…·제주` 로 끝난다. **주택멸실현황 자체가 시도
단위 승인통계**이고, 통계누리 OPEN API(신청 필요)도 같은 `formId` 를 준다.

### 안분하지 않는다

경기 전체 멸실을 가구수 비중이나 노후 재고 비중으로 나눠 남부에 배분할 수는 있다.
**하지 않는다.** 무엇으로 나누느냐에 따라 값이 달라지고 어느 쪽도 근거가 없는데,
그 값은 화면에서 공급 과부족의 **기준선** 노릇을 한다. 기준선이 추정이면 그 위의
판단이 전부 흔들린다.

### K-apt 전수를 해마다 떠서 비교한다

`kapt_units` 에 `first_seen`·`last_seen` 을 둔다. 전수를 다시 받으면 이번에 본
단지의 `last_seen` 이 오늘로 올라가고, **안 보인 단지는 옛 날짜로 남는다.** 그것이
그 사이 사라진 단지다.

행을 스냅샷마다 쌓지 않는 이유: 같은 단지 수천 곳을 해마다 쌓으면 같은 값이
되풀이되는데 우리가 묻는 것은 "언제 사라졌나" 하나뿐이다. 유니크 키를 그대로 둘 수
있어 `migrate.py` 의 ADD COLUMN 으로 끝나는 것도 이유다 — SQLite 는 유니크 제약을
바꾸려면 표를 다시 만들어야 한다.

`kapt_runs` 가 **돌린 사실 자체**를 남긴다. 이게 없으면 `last_seen` 이 옛 날짜인
단지를 보고 사라졌다고 할 수 없다 — 그 시군구를 아예 안 돌렸을 수도 있기 때문이다.
둘은 전혀 다른 뜻인데 표에서는 똑같이 보인다.

공표값은 아니지만 **우리가 직접 관측한 값**이라 안분 추정보다 낫고, 해가 갈수록
정확해진다. 다만 **아파트 멸실만** 잡는다.

### 건축물대장도 전수를 뜬다

K-apt 는 의무관리대상 아파트뿐이라 단독주택 멸실을 못 잡는다 — 2024년 전국 멸실
85,069호 중 **단독이 39,169호(46%)** 다. 그래서 건축HUB 건축물대장 표제부도 전수로
받는다(`ingest_bldrgst`). 처음 뜬 전수(2026-10):

    법정동 439개 · 건축물 323,915동 · 어긋난 곳 0 · 호출 약 5,300
    단독주택 126,080동 · 공동주택 50,024동(1,497,858세대)

**다른 자료와 맞아떨어진다.** 단독 126,080 + 공동 1,497,858세대를 합치면
1,623,938호인데, KOSIS 경기도기본통계의 2024년 경기 남부 8개 시 주택수가
1,608,771호다 — **1% 차이**다. 기관도 방식도 다른 두 자료가 이만큼 맞는다.

#### 이 API 는 조용히 0 을 돌려준다

가장 중요한 성질이고, 안 잡으면 **거짓 멸실을 만들어 낸다.** 간헐적으로 빈 결과를
`resultCode: 00`(정상)과 함께 보낸다.

법정동 439개를 두 번 세었더니 **265,799동과 295,324동**이 나왔다(10% 차이). 수원
권선구 세류동(5,565동)이 어떤 호출에서는 0 이었고, 화성 동탄구는 통째로 0 이 나와
'건축물이 없는 구' 로 보였다. 가드를 넣고 제대로 받으니 323,915동이었다 — 세어만
봤을 때보다 **10% 더 많다.**

K-apt 에서 겪은 것과 같은 모양인데(일시 오류에 재시도가 없어 시군구 6곳이 통째로
빠졌다) 결과는 더 나쁘다. 멸실을 재려고 만든 구조가 거꾸로 멸실을 지어낸다.

그래서 셋을 둔다.

1. 법정동마다 **총 건수를 먼저 받아 두고**(`expected`) 다 받은 뒤 대조한다
2. 어긋나면 그 법정동을 **비교에서 뺀다**. `bld_runs` 에 `expected`·`fetched` 를
   둘 다 남겨 나중에 판단할 수 있게 한다
3. 0 이 오면 쉬었다 네 번까지 다시 묻고, 끝까지 0 이면 **그 쪽은 실패로 올린다**
   (쪽 하나가 비면 법정동 전체를 실패 처리한다 — 반쯤 받은 것이 제일 나쁘다)

호출 사이에도 간격을 둔다. 439콜을 24초에 몰아쳤을 때 뒤쪽이 통째로 0 이었다.

#### 겪은 함정 둘

- **법정동 목록을 API 가 주지 않는다.** 행정표준코드관리시스템에서 받아
  `backend/data/manual/bjdong_*.tsv` 에 둔다. 우리 17개 구에 439개(동 198 + 리 241)
  이고, 아파트가 있는 법정동만 세면 177개뿐이다 — 단독주택 멸실을 잡으려면 2.5배
  차이가 그대로 구멍이 된다.
- **한 법정동을 한 문장으로 넣으면 SQLite 가 죽는다.** 컬럼 11개 × 수천 행이
  `too many SQL variables` 에 걸린다. 과천시(4,353동)로 시험했을 때는 안 걸렸다 —
  **큰 법정동에서만 터지므로 작은 데서 시험하면 안 보인다.** 400행씩 끊어 넣는다.

#### 말소를 직접 주는 오퍼레이션은 없다

멸실의 정의가 '건축물대장 말소' 라 그것부터 찾았다. 오퍼레이션 10개가 표제부·
기본개요·층별개요·전유공용면적·주택가격·전유부·오수정화시설·총괄표제부·부속지번·
지역지구구역인데 **말소·철거·멸실 관련이 하나도 없다.** 말소된 건축물은 조회에서
그냥 빠진다. 그래서 여기서도 **스냅샷 비교**를 한다 — K-apt 와 구조가 같고 범위만
넓다.

### 멸실 숫자는 두 번째 스냅샷부터 나온다

첫 스냅샷(2026-10)만으로는 비교할 상대가 없다 — K-apt(아파트)와 건축물대장(주택 전체)
둘 다 그렇다. 스냅샷은 **놓치면 복구할 수 없다.** 다른 적재는 늦게 돌려도 과거 값이
그대로 오지만, 스냅샷은 '그때 무엇이 있었나' 라서 지나가면 그해는 영영 빈칸이 된다.
그래서 둘을 둔다.

- 작업 스케줄러 — `snapshot_yearly.ps1` 를 52주마다 돌린다. 등록 명령은 그 파일
  맨 아래 주석에 있다
- `checkup` 의 신선도 — 마지막 스냅샷이 400일을 넘기면 알린다

그때까지 '적정 공급 = 가구 증가 + 멸실' 을 경기 남부로 **완전히** 내리지는 못한다.
경기 전체로 보면 2024년 가구 증가 92,100 에 멸실 24,903 이라 멸실이 21% 를 차지한다 —
빼고 쓰면 적정선이 그만큼 낮게 잡힌다.

## 못 하는 것

- **경기 남부 주택 전체 준공.** K-apt 로 아파트 입주 물량은 메웠지만 빌라·단독을
  포함한 준공은 여전히 시도 단위뿐이다.
- **CSV 자동화.** KOSIS OpenAPI 키를 받으면 손으로 받는 CSV 를 자동화할 수 있다. 키
  없이는 한 줄도 안 온다(`err:10 인증KEY값이 누락되었습니다`). ECOS 처럼 샘플 키로
  미리 만들어 두는 길은 없다.
