# 한국부동산원 공표 통계 (R-ONE)

거시 탭이 쓰는 데이터. 우리가 실거래를 모아 만드는 값과 달리 **남이 계산해 공표한**
값이라, 검산에는 쓸 수 있어도 우리 숫자를 대체하지는 않는다.

실거래·단지·입지 수집은 [데이터 파이프라인](data.md) 참조.


거시 분석 탭이 쓰는 데이터. 공공데이터포털 `15134761`, 무료, 이용허락범위 제한 없음.

### 인증키가 따로다

API 유형이 **LINK** 라 data.go.kr 이 중계하지 않는다. 즉 `MOLIT_SERVICE_KEY` 를
**쓸 수 없고** 한국부동산원에서 따로 발급받아 `REB_SERVICE_KEY` 로 넣는다.

키가 없으면 샘플 모드로 동작한다 — 어떤 요청이든 **5행 고정**이고 `pIndex`·`pSize`
가 무시된다. 적재는 못 하지만 `scripts/probe_reb.py` 의 구조·지역 대조는 돈다.

### 쓰는 통계표 (전부 월간·시군구)

| 코드 | 내용 | 단위 |
|---|---|---|
| `A_2024_00045` | 매매가격지수_아파트 | 지수 |
| `A_2024_00050` | 전세가격지수_아파트 | 지수 |
| `A_2024_00060` | 평균매매가격_아파트 | **천원** |
| `A_2024_00061` | 평균단위매매가격_아파트 | **천원/㎡** |
| `A_2024_00062` | 중위매매가격_아파트 | **천원** |
| `A_2024_00072` | 평균 매매가격 대비 전세가격 | % |
| `A_2024_00554` | (월) 행정구역별 아파트매매거래현황 | **호** |

거래량 표(`00554`)는 항목이 둘이다 — `100001` 동(호)수, `100002` 면적(천㎡). 호수만
쓴다(`DEFAULT_ITM_ID` 와 같아서 따로 지정하지 않는다). 2006-01 부터 있어 17개 시군구
3,252행이다. 평형 구성은 평균/중위 괴리로 보므로 면적 항목은 안 쓴다.

### 함정 둘 — 둘 다 검사가 잡았다

**1. 지역코드(`CLS_ID`)는 표마다 다르다.**

지수표에서 뽑은 코드를 가격표에 쓰면 **다른 지역**이 온다. 같은 `530091` 이
지수표에서는 화성시 만세구인데 평균매매가격표에서는 부천시 원미구다. 가격표에는
`(구)원미구` 같은 옛 행정구역 항목이 더 있어 번호가 3칸 밀린다(지수표 분류 236개,
가격표 245개).

그래서 코드를 박지 않고 **표마다 `SttsApiTblItm.do` 로 받아 `ITM_FULLNM` 경로로
찾는다**(`경기>서해안권>화성시>만세구`). 끝 조각이 정확히 같아야 하므로
`(구)원미구` 는 걸러지고, 후보가 둘 이상이면 고르지 않고 실패시킨다.

받은 뒤에도 `CLS_FULLNM` 으로 한 번 더 검산한다. **틀린 코드는 오류가 아니라 남의
지역 값으로 조용히 돌아온다** — 화성시 분구 때 실거래 0건으로 겪은 것과 같다.

**2. 금액 단위는 만원이 아니라 천원이다.**

㎡당 단위가격을 만원으로 읽으면 평당 2.2억이 나온다. 그런 값은 '비싼 동네' 로만
보여서 조용히 지나간다. API 가 `UI_NM` 으로 단위를 알려 주므로 **받은 값을 고치지
않고 단위를 함께 저장**하고(`RebStat.unit`), `services/macro.py` 한 곳에서만
환산한다. 적재에서 바꾸면 공표값과 저장값이 달라져 나중에 대조할 수 없다.

### 거래량은 가격과 다른 축이다 — 그래서 넣었다

가격 지표 여섯 개는 서로 거의 같은 말을 한다. 거래량은 다른 말을 한다.

```
Spearman(12개월 거래 배수, 12개월 가격 변화) = 0.352   (n=13)
   비교: Spearman(부동산원 평당가 순위, 모델 구 계수 순위) = 0.882
```

뒤쪽은 **같아야 정상인** 두 값이고, 앞쪽은 다른 것이 정상이다. 실제로 순서가 크게
엇갈렸다.

```
용인시 기흥구  거래 2.01배  가격 +12.7%      수원시 영통구  거래 1.28배  가격 +14.8%
과천시        거래 0.76배  가격  +7.8%      오산시        거래 1.04배  가격  +1.4%
```

과천은 거래가 5년 평균보다 **줄었는데** 가격이 올랐다. 가격만 봐서는 안 보인다.

**절대 건수로는 지역끼리 비교할 수 없다.** 과천 월 33건, 화성 동탄구 월 1,137건이다
(34배). 그래서 `volume_support` 는 **그 구의 직전 5년 연평균 대비**로 바꿔 같은 축에
놓는다. 비교할 과거 5년이 필요하므로 `VOL_MIN_MONTHS = 72`, 화성 분구 4곳은 빠진다.

**마지막 달은 신고 지연으로 과소집계될 수 있다.** 재 봤다 — 13곳 중 4곳이 직전
12개월 평균의 0.8배 밑이었지만(기흥 0.32·과천 0.34) 9곳은 정상이라 전역에 걸친
지연은 아니었다. 12개월 **합**이라 한 달의 영향은 묻힌다: 마지막 달을 빼고 다시 재니
배수가 최대 0.11 바뀌고 순위는 인접 한 쌍만 뒤집혔다. 그래서 포함하고 사실만 적는다.

### 지수의 표본 두께를 같이 보여 준다

거시 분석 탭은 17개 구 지수를 **같은 굵기의 선**으로 그린다. 그런데 그 지수를 만든
거래가 과천은 월 33건, 동탄은 월 1,137건이다. 같은 '전고점 대비 -5%' 가 무게가
다른데 화면에서 구분되지 않았다.

값을 고치지 않고 **얇다는 사실을 같이 보여 준다**(`sample_depth`). '얇다' 기준은
17곳 중위값의 절반 — 절대 건수로 선을 그으면 지역 규모가 바뀔 때 거짓이 된다.

주의: 이건 **대리지표**다. 한국부동산원 지수의 실제 표본 설계는 공표 거래 건수와
다르다. "그 구에서 한 달에 몇 건이 거래되는가" 까지만 말한다.

### 평균 ÷ 중위 — 구 계수 가정을 검산한다

우리 모델은 구마다 계수 하나(`sgg_*`)를 둔다. 그게 뜻을 가지려면 구가 어느 정도
균질해야 한다. 공표되는 평균과 중위를 나누면 그 가정이 검산된다. 이미 적재된
두 표(`00060`·`00062`)만 쓰므로 추가 적재가 없다.

```
수원시 영통구 +25.0%   화성시 병점구 +14.2%   의왕시 +11.0%
용인시 처인구  +0.8%   화성시 만세구  -3.6%   수원시 팔달구 -4.3%
```

영통구는 평균이 중위보다 25% 높다 — 광교와 영통이 한 구에 섞여 있다는 뜻이다.
팔달·만세구는 반대로 평균이 중위보다 **낮다**(고가 쪽이 얇다).

평균 평수(= 한 채 평균가 ÷ 평당가)도 같은 두 표에서 공짜로 나온다. 팔달 21.5평 ~
수지 27.8평이고, 평당가 순위와 한 채 가격 순위가 왜 다른지가 여기서 설명된다.

### 기준시점을 코드에 박지 않는다

지수는 기준시점이 100 이다. 그 시점을 "2026년 1월 = 100" 이라고 주석에 적었다가
틀렸다 — 받아서 보니 **2026년 6월**이었고, 데이터로도 202606 의 값이 17개 시군구
전부에서 정확히 100.000 이었다.

한국부동산원은 주기적으로 기준을 옮긴다(리베이스). 박아 두면 그때 조용히 거짓이
된다. 그래서 적재할 때 통계표 메타의 `RPSTUI_NM`(`기준시점 : 2026.06.=100.0`)을
받아 `RebStat.base` 에 저장하고, 화면은 그것을 읽는다. 리베이스되면 다음 적재에서
저절로 따라간다.

### 화성시 분구는 시계열이 짧다

만세·효행·병점·동탄구는 **2026년 2월부터**만 공표된다. 분구 시점에 통계가 새로
시작한 것이다. 없는 기간을 0 이나 보간으로 채우지 않는다 — 화면이 선을 중간에서
시작하고 그 사실을 적는다. 긴 추이가 필요하면 분구 전 화성시 전체를 쓰고 그렇게 적는다.

### 모델 검산으로 쓴다

평당 매매가격 순위가 분해 모델의 구 계수 순서와 거의 그대로 맞는다.

```
과천시 8,452만원/평 (모델 +117.4%)   안양시 동안구 3,913 (+21.2%)
화성시 동탄구 3,719 (+17.5%)         용인시 수지구 3,606 (+18.9%)
수원시 영통구 3,411 (+21.0%)
```

서로 다른 데이터와 방법인데 순위가 맞는다는 것이 둘 다에 대한 확인이다. 어긋나면
둘 중 하나를 의심해야 한다.
