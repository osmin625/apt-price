# 기술주 가치 — 시가총액을 지금 사업·기대 기술·설명 안 된 몫으로

주식 '기술주 가치' 탭이다(2026-11-14 요청). 기대가 주가의 큰 몫인 기술주에서, 사람들이 기대하는 기술이 언제
실현되고 그때 얼마를 벌면 지금 주가가 맞는지, 그리고 실현 때 주가가 지금 주가와 어떻게 견주어지는지를 본다.
부동산 [반영 분해](../analysis/macro-model.md#반영-분해--방향은-이론-크기는-데이터)처럼 '값을 몫으로 나눈다'.

## 나누는 식

    시가총액 = 지금 사업 + Σ 기술 k 의 지금 값 + 설명 안 된 몫

    지금 사업        = E0 / (r − g)                          E0 = 지난 12개월 이익. 적자면 0
    기술 k 의 지금 값 = p_k · (P_k · PER_k) / (1 + r)^t_k     t_k = 실현 해의 한가운데까지 남은 해
    r(할인율)        = 미국 10년 국채 + 베타 × 주식 위험 프리미엄

- **지금 사업은 성장 없는 영구 이익**이 기본이다(g = 0, 화면에서 0~4%). 고전적인 '현재 이익의 값 + 성장 기회의 값'
  분해에서 앞의 것이다. 성장 몫을 기대 기술 쪽에 모으려고 기본을 0 으로 둔다.
- **이익 기준은 영업이익 세후가 기본**이다. 순이익에는 영업 밖의 일회성 손익이 들어 있다 — 알파벳은 2026 2분기에
  보유 지분 증권의 공정가치 이익이 990억 달러여서(EDGAR `EquitySecuritiesFvNiGainLoss`), 12개월 순이익이 영업이익보다
  컸다. 세율은 미국 연방 법정 21%. IBM 처럼 영업이익을 XBRL 로 내지 않는 회사는 순이익을 쓴다.
- **적자면 지금 사업을 0 으로 둔다.** 적자를 영원히 이어 가는 값으로 빼면 디웨이브 같은 종목은 지금 사업이 음수가
  되고 기대 몫이 그만큼 부푼다. 적자는 기대 기술에 쓰는 돈으로 본다.
- **거시는 할인율로 들어간다.** 10년 국채는 지수 분석과 같은 FRED GS10 월평균이다. 베타는 최근 최대 60달 종목 월 수익률
  (수정 종가)을 S&P 500 월 수익률에 회귀한 기울기, 적어도 24달. 위험 프리미엄 5% 는 관례이고 화면에서 3~7%.
  화면은 '10년 금리 +1%p 면 지금 사업·기대 기술이 몇 % 줄어드나' 를 같이 낸다 — 먼 해의 이익일수록 크게 준다.

## 역산과 실현 때 주가

시나리오는 가정이다. 그래서 같은 줄에 **주가에서 나오는 값**을 둔다.

- **지금 주가가 맞으려면** — 다른 기술은 표대로 두고, 남는 몫을 이 기술 하나가 다 설명한다면
  - 필요 이익 P* = (시가총액 − 지금 사업 − 다른 기술) · (1 + r)^t / (p · PER)
  - 필요 시점 t* = ln(p · P · PER / 남는 몫) / ln(1 + r) — 지금 실현돼도 모자라면 '모자람'
- **실현 때 주가** = (그때의 지금 사업 이익 + 그 기술 이익) × PER ÷ 지금 주식 수. 확률은 넣지 않는다('실현됐다면').
  지금 주가에서 그 주가까지의 연 수익률이 할인율보다 높으면 초록, 낮으면 빨강. 주식 수가 늘면(희석) 더 낮다.

계산은 화면에 있다(`frontend/src/stock/techvalue/model.js`) — 시나리오를 바꿔 보려면 브라우저가 계산해야 하고
정적 사이트에는 서버가 없다. 같은 식을 파이썬으로 따로 써서 `scripts/verify_tech_value.py` 가 대조한다(node 가
있을 때). 역산한 이익·시점을 시나리오에 넣으면 설명 안 된 몫이 0 이 되는지도 본다.

## 시나리오

기본값은 `backend/app/stock/scenarios.py` 에 있다. **근거 문구는 '무엇을 언제' 까지만** — 회사가 발표했거나 이미
일어난 일이다. 실현 해·그해 순이익·확률·그때 PER 은 이 저장소의 가정이고 화면이 그렇게 적는다(루트 CLAUDE.md
'추정을 사실처럼 보여 주지 않는다'). 고를 때 지킨 것은 그 파일 머리에 있다.

## 출처

| 무엇 | 출처 | 주기 |
|---|---|---|
| 주가 | Alpha Vantage — 최근 100일 일봉(지금 주가), 상장 때부터 월봉 수정 종가(베타·그림) | 매일 06:30 동기화 |
| 재무 | 미국 SEC EDGAR companyfacts — 순이익·매출·영업이익·주식 수 | 분기(10-Q·10-K) |
| 10년 국채 | FRED GS10(지수 분석과 같은 계열) | 월 |

정하면서 버린 것(2026-11-14 에 재 봄):

- **Nasdaq 사이트 API 를 주 출처로 정했다가 버렸다.** 키 없이 10년치·분할 조정된 값을 주지만, 파이썬 요청에는 403
  이고 브라우저인 척해야 받는다 — 사이트가 자동 요청을 막아 둔 것이라 쓰지 않는다. 야후도 같은 까닭이다. Stooq 는
  봇 차단 화면만 준다.
- **Alpha Vantage 무료 키로는 일봉 전체가 안 된다**(유료). 월봉 수정 종가는 상장 때부터 무료라 과거는 월봉으로 잇는다.
  하루 25번·초당 1번이고 종목당 두 번 쓴다. 받은 일봉의 지난달 마지막 종가와 월봉 종가를 맞춰 보고, 수정 종가의
  한 달 변화가 로그 1.5 를 넘으면 분할 조정 누락으로 보고 넣지 않는다(`scripts/ingest_stock.py` 의 `company_problems`).
- **주식 수는 dei:EntityCommonStockSharesOutstanding 이 아니다.** 주식 종류가 여럿인 회사(알파벳 A·B·C)는 그 값이
  종류별로만 있고 companyfacts 가 빼고 준다. 대차대조표 합계(CommonStockSharesOutstanding)를 쓰고, 더 오래됐으면
  희석 가중평균을 쓴다(IBM).
- **4분기 값은 따로 없다.** 1년 − 9개월로 만든다. 지난 12개월 합이 10-K 연간 값과 같은지를 verify 가 실제 자료 전부로
  본다(`app/stock/fundamentals.py`).
- **삼성전자는 신청 대기**다 — 공공데이터포털 '금융위원회_주식시세정보' 가 지금 키로 403(미신청), 재무는 OpenDART 키가
  필요하다. 승인되면 `companies.py` 에 더한다.

## 반영 분해 — 지난 1년 주가 변화를 요인별로

시나리오는 앞날의 가정이고, 반영 분해는 **지나간 1년을 잰 것**이다(`backend/app/stock/reflect.py`, 화면 맨 아래 카드).
부동산 [반영 분해](../analysis/macro-model.md#반영-분해--방향은-이론-크기는-데이터)와 같은 식이다.

    1년 변화(t) = a + Σ b_j · s_j · z_j(t − 발표 시차_j),    b_j ≥ 0

| 정한 것 | 값 | 이유 |
|---|---|---|
| 거시 요인 | 지수 분석의 S&P 500 짝 여섯(`indicators.PAIRS['spx']`) — 움직임의 정의·발표 시차·상식의 방향 그대로 | 지수 분석과 다른 방향을 따로 두면 두 탭이 다른 말을 한다 |
| 실적 요인 | 지난 12개월 매출 상승률(%), 이익률 1년 변화(%p) — 영업이익률, 없으면(IBM) 순이익률 | 순이익 상승률은 적자 회사(디웨이브·예전 테슬라)에서 정의되지 않는다 |
| 시차 | 발표 시차만(물가·M2·실업률 1달) | 부동산은 금리가 수요로 가는 데 6달을 뒀지만, 주가는 알려지는 날 움직인다 |
| 실적 값 | 그달 말까지 처음 제출된 값(`fundamentals.ttm(as_of, first=True)`) | 나중에 고쳐진 숫자로 과거를 설명하면 그때 몰랐던 것을 안 셈이다 |
| 크기 | 절편 자유·기울기 0 이상 최소제곱(scipy `nnls` 를 가운데로 옮겨) | 데이터가 상식과 반대로 움직이면 0(반영 안 보임) — 부동산과 같은 규칙 |
| 범위 | 24달 덩어리 부트스트랩의 5~95% = '80% 범위' | 아래 |
| 표본 | 요인이 모두 갖춰진 달이 60달 이상일 때만 | 디웨이브는 상장이 2022 년이라 아직 나누지 않는다 |

**범위는 이름이 아니라 잰 덮는 비율로 정했다.** 부동산처럼 12달 덩어리의 10~90% 로 시작했는데, 합성 자료(끈적이는 요인 +
12달 충격이 겹치는 1년 창)에 참값을 심어 재 보니 67% 만 덮었다. 덩어리 길이와 분위를 바꿔 잰 값은 `reflect.py` 머리에
있고, 24달 5~95% 가 80% 안팎이다. 달마다 뽑으면 같은 분위로도 절반도 못 덮는다. `scripts/verify_stock_reflect.py` 가 매번
다시 잰다(70~90% 를 벗어나면 실패).

**읽을 때 주의할 것** — 같은 달에 같이 움직인 크기이지 원인의 크기가 아니다. 요인 여덟을 열 몇 해의 겹치는 1년 창에 맞추면
서로 얽힌 요인끼리 몫을 주고받는다. 그래서 화면 ⓘ 에 기간을 반으로 나눠 맞춘 설명력을 같이 적는다. 2020 년처럼 돈이
크게 풀린 해에 주가가 크게 오른 종목은 M2 에 큰 크기가 붙을 수 있다 — 그해의 동행이 크기를 끌고 간다.
