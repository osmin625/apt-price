# 차트 — 앱의 차트 유형·오버레이·보조지표를 보는 법

주식의 '차트' 탭은 증권사 앱(HTS·MTS)이 주는 차트 유형·오버레이·보조지표를 하나씩 설명한다(2026-11-27 요청 —
"NH증권 앱에서 지원하는 차트 지표 항목들을 보는 방법"). 항목마다 계산·흔한 설정·읽는 법·함정이 있고, 가격으로
그릴 수 있는 것은 같은 합성 가격 위에 식을 돌린 예시 그림이 붙는다.

코드는 `frontend/src/stock/charts/`(목록·계산·합성 가격)와 `frontend/src/stock/views/ChartView.jsx`(화면)다.
백엔드를 부르지 않는다.

## 목록은 일반 목록이다

NH투자증권 앱(나무·QV)의 공식 지표 목록은 공개된 곳이 없다(2026-11-27 에 찾아봄 — 공식 도움말에 목록이 없고,
나무 MTS 를 다룬 블로그 글은 비공식이며 개수도 '30가지 이상' 이라고만 한다). 사람에게 앱 화면 캡처를 받거나 일반
목록으로 가는 것 가운데 **일반 목록**을 골랐다. 그래서

- 국내 HTS 에 흔한 이름을 썼다(이격도·투자심리선·VR·ADR·삼선전환도·역시계곡선 등). 앱마다 이름·묶음·기본값이
  다를 수 있고 화면 머리말 ⓘ 가 그렇게 적는다.
- 앱 목록을 받으면 이름·묶음을 그에 맞추고, 빠진 것을 더한다. 이 문서의 '앱과 맞추기' 에 남긴다.

| 묶음 | 무엇 |
|---|---|
| 차트 유형 | 캔들·바·라인·산·헤이킨아시·렌코·삼선전환도·P&F·카기·이큐볼륨·역시계곡선 |
| 오버레이 | 가격 위에 겹치는 것 — 이동평균(단순·지수·가중·그물망)·밴드·채널·일목·SAR·피봇·VWAP 등 |
| 보조지표 | 가격 아래 칸 — 추세·모멘텀(과열)·변동성·거래량·시장 강도(지수)·수급·심리 |

개수는 소스(`catalog.js` 의 `ITEMS`)가 정하고 화면 머리에 그 자리에서 센다 — 여기 적지 않는다.

## 예시 그림

**모든 지표가 같은 합성 가격**(오름 → 옆걸음 → 급락 → 되오름) 위에 그려진다(`frontend/src/stock/charts/sample.js`). 지표를 바꿔 가며
같은 구간에서 어떻게 다르게 반응하는지 견주라는 것이다. 앞 60일은 계산에만 쓰고 그리지 않는다 — 52·60일 창을
쓰는 지표(일목 선행 스팬 B·그물망)가 그림 첫날부터 값을 갖게 하려고.

| 정한 것 | 이유 |
|---|---|
| 손으로 그리지 않고 식을 돌린다(`frontend/src/stock/charts/calc.js`) | 늦게 반응하는 지표는 그림에서도 늦어야 그 지표의 실제 모습이다(`frontend/src/stock/techniques/synth.js` 와 같은 원칙) |
| 정의가 여럿이면 흔한 쪽 하나 | ATR·RSI·ADX 는 와일더 평활, 모멘텀은 비율(C ÷ Cₙ × 100, 국내 관례), 스토캐스틱은 14·3·3. 고른 쪽을 창의 '계산' 에 적는다 |
| 시간 축 없는 차트(렌코·삼선전환·P&F) | 벽돌·선·열을 캔들처럼 늘어놓는다. 가로축이 '칸' 이다 |
| 그리지 않는 것 | 시장 강도(등락 종목 수)·수급(투자자별 매매·신용·공매도·예탁금·풋콜·VIX)·신심리도(앱마다 식이 다름)·역시계곡선(산점도)·추세선·매물대(가로 막대) — 지어낸 등락 종목 수를 그리면 실제 자료처럼 읽힌다 |
| 바·산 차트 | `ExampleChart` 에 `ohlc`·`area` 를 더했다 |

종목을 골라도 이 탭은 합성 가격을 그대로 쓴다 — 종목 일봉이 최근 100일뿐이라 52·60일 창을 쓰는 지표를 채우지 못한다
([picks.md](picks.md) '단기 매매 — 보류' 와 같은 까닭). 고르면 그렇다고 한 줄 적는다.

## 단기 매매 탭과의 관계

같은 기법이 단기 매매 탭에 있으면(`short`) 창에서 그리로 잇는다 — 그 탭은 규칙을 실제 S&P 500·KOSPI 에 돌린 성적이
있다([trading.md](trading.md)). 설명을 두 곳에 쓰지 않으려고 이 탭은 '보는 법', 그 탭은 '그대로 사고팔면 어땠나' 를 맡는다.

## 앱과 맞추기

앱 목록을 받으면 할 일:

1. 앱의 묶음 이름으로 `catalog.js` 의 `GROUPS` 를 바꾸고, 항목의 `name` 을 앱 표기에 맞춘다(영문 `en` 은 그대로).
2. 앱에만 있는 지표를 더한다 — `calc.js` 에 식, `types.js`·`trend.js`·`volume.js` 에 항목.
3. 앱의 기본값이 다르면 `set` 에 앱 값을 먼저 적는다.

## 검증

`scripts/verify_charts.py` — id 가 겹치지 않는지·단기 매매로 잇는 id 가 있는지(소스로), 그림마다 선 길이·빈 값·NaN,
ATR·RSI·CCI·%R·MFI·CMF·스토캐스틱·ADX·아룬·얼티밋·VR·OBV 가 파이썬으로 따로 쓴 식과 같은지, 단순 평균 ATR 이 그
비교에 걸리는지, 지그재그·카기가 실제로 꺾이는지. 지그재그·카기는 처음에 '방향 없음' 으로 시작해 극값이 늘 오늘 값이
되는 바람에 한 번도 꺾이지 않았다 — 그 검사가 그래서 있다.
