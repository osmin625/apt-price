# 배포 — 로컬은 동적, 공개는 정적

모델을 돌리는 것과 결과를 보여 주는 것은 필요한 것이 다르다.

| | 필요한 것 | 어디서 |
|---|---|---|
| 데이터 적재 · 모델 적합 · 매물 붙여넣기 | numpy·pandas·statsmodels, 실거래 11만 건, 수십 초의 계산, DB 쓰기 | 로컬 (동적) |
| 결과 보기 | JSON 한 묶음 | 어디서나 (정적) |

그래서 무거운 쪽은 로컬에 두고, 가벼운 쪽만 정적 사이트로 올린다. 정적 사이트는
백엔드가 없고 파이썬도 필요 없다.

## 흐름

```
로컬 대시보드 (동적)
  적재 · 적합 · 매물 붙여넣기
        │
        │  export_static.py   화면이 부르는 요청을 실제 ASGI 앱으로 실행해
        │                     응답을 JSON 파일로 떨어뜨린다 (80개 파일 · 8.2MB · 50초)
        ▼
  frontend/public/snapshot/
        │
        │  npm run build:static   VITE_DATA_MODE=static 으로 빌드.
        │                         api.js 가 /api 대신 스냅샷 파일을 읽는다
        ▼
  frontend/dist/
        │
        │  gh-pages 에 고아 커밋 하나로 강제 푸시
        ▼
  정적 사이트
```

한 번에 돌리는 것은 `sync_static.ps1` 이다.

```powershell
.\sync_static.ps1              # 내보내기 + 빌드 + 배포
.\sync_static.ps1 -NoPublish   # 배포 없이 로컬에서 확인만
.\sync_static.ps1 -NoQuotes    # 호가(매물 순위·단지 상세) 제외
```

배포 전 확인:

```powershell
cd frontend; npm run preview:static   # http://localhost:4173/apt-price/
```

## 정적 사이트에 실리는 것

`App.jsx` 의 `TABS` 에서 `static: true` 인 것만 보인다.

| 탭 | 정적 | 이유 |
|---|---|---|
| 시장 분석 | O | 요인별 보정계수 + 도보거리 상세 창까지 전부 |
| 매물 순위 | O | 단지명을 누르면 단지 상세도 열린다 |
| 지도 | X | 만들 수는 있지만 응답이 기간당 1.2MB 라 스냅샷이 무거워진다 |
| 분해 모델 | X | 같은 이유. 필요해지면 목록에 넣고 `static: true` 만 켜면 된다 |
| 매물 분석 | **불가** | 붙여넣은 텍스트를 그 자리에서 파싱·평가한다. 미리 파일로 만들 수 없다 |

**눌리는데 실패하는 것을 두지 않는다.** 삭제 버튼과 새로고침은 정적에서 숨긴다.
그래도 쓰기 요청이 가면 `api.js` 가 405 로 사실을 적는다 — 조용히 실패하지 않는다.

## 파일 이름 규칙 — 양쪽이 같아야 한다

`scripts/export_static.py` 의 `target_of()` 와 `frontend/src/api.js` 의
`snapshotPath()` 는 **같은 규칙**이어야 한다.

```
/api/health                        -> health/default.json
/api/model/factors?months=12       -> model/factors/months=12.json
/api/complexes/14?months=24        -> complexes/14/months=24.json
/api/quotes/ranking?basis=market
    &days=7&months=12              -> quotes/ranking/basis=market~days=7~months=12.json
```

쿼리는 **이름순으로 정렬**한다. 프론트엔드가 파라미터를 넣는 순서는 화면마다
다를 수 있어서, 정렬하지 않으면 같은 요청이 다른 파일을 가리킨다.

한쪽만 바꾸면 화면은 404 를 받고, 그건 **"데이터가 없다" 로 보인다** — 이 저장소가
가장 경계하는 조용한 실패다. 그래서 규칙을 양쪽 주석에 같이 적어 두었다.

내보낼 요청 목록은 `export_static.py` 의 `build_plan()` 하나에만 있다. 화면에
새 필터 조합이 생기면 여기에 넣어야 한다 — 넣지 않으면 그 조합만 404 가 된다.

## 왜 TestClient 인가

서비스 계층을 직접 부르면 라우터가 하는 일(기본값, 검증, 직렬화)을 내보내기 쪽에서
다시 구현해야 하고, 그러면 **정적 사이트와 동적 사이트가 조용히 다른 값을 내기**
시작한다. `TestClient` 는 실제 ASGI 앱을 그대로 호출하므로 같은 코드를 지난다.

응답은 `r.content` 를 **바이트 그대로** 쓴다. 파싱해서 다시 쓰면 그 순간부터
부동소수점 표기나 키 순서가 달라질 수 있다. 다시 만들지 않는 것이 가장 확실하다.

서버를 띄우지 않아도 되니 작업 스케줄러에서 돌리기도 쉽다 — 포트 충돌도, 종료
처리도 없다.

## 왜 고아 커밋으로 강제 푸시하나

스냅샷은 8.2MB 이고 내보낼 때마다 거의 전부 달라진다(적정가가 그 기간 실거래로
다시 계산되므로). 그걸 `gh-pages` 에 쌓으면 이력이 **하루 8MB 씩** 불어난다.
한 달이면 240MB 다.

그래서 매번 `dist` 안에 빈 저장소를 만들어 커밋 하나만 두고 force push 한다.
브랜치에는 항상 커밋이 하나뿐이라 이력이 늘지 않는다. 정적 사이트에 이력이 필요한
경우는 없다 — 필요한 이력은 소스 저장소에 있다.

`.nojekyll` 을 같이 둔다. 없으면 GitHub Pages 가 Jekyll 로 처리하면서 `_` 로
시작하는 파일·디렉터리를 조용히 뺀다. 지금 구조에는 없지만, 나중에 생겼을 때
"파일이 왜 404 지" 로 시간을 버리지 않도록 미리 둔다.

## base 경로

GitHub Pages 는 `https://<user>.github.io/<repo>/` 하위에 올라간다. `base` 를 안
맞추면 빌드 결과가 절대 경로 `/assets/...` 를 가리켜 전부 404 가 된다.

`frontend/.env.static` 의 `VITE_BASE` 로 정한다. 루트 도메인에 올릴 때는 `/` 로
바꾼다. 환경변수를 셸에서 넘기지 않고 파일로 두는 이유는, 윈도우에서 `set` /
`$env:` / npm 스크립트를 섞다 보면 어느 하나에서 조용히 빠지고 그러면 **정적
모드가 아닌 채로 빌드돼** 백엔드를 찾다가 전부 실패하기 때문이다.
`vite build --mode static` 은 이 파일을 확실히 읽는다.

## 주기 동기화

작업 스케줄러에 하루 한 번 등록한다. 실거래가는 하루 단위로 갱신되므로 이보다
자주 돌릴 이유가 없다. 등록 명령은 `sync_static.ps1` 맨 아래 주석에 있다.

로그는 `sync_static.log` 에 쌓인다(`.gitignore` 의 `*.log` 에 걸린다). 실패는
종료 코드로도 올라가므로 스케줄러의 마지막 결과에서 보인다 — **내보내기가 반쪽이면
화면에는 아무 표시 없이 옛 값이 남으므로**, 조용히 넘기지 않는 것이 중요하다.

## 공개 범위 — 호가는 실거래가와 성격이 다르다

실거래가는 국토교통부가 공개하는 데이터라 그대로 올려도 된다. **호가는 다르다.**
네이버 부동산에서 붙여넣은 값이고, 이 저장소는 애초에 네이버 자동 수집을 약관
문제로 배제했다. 공개 사이트에 호가를 그대로 싣는 것은 같은 문제를 다른 경로로
들이는 셈이다.

- 저장소가 **private** 이면 무료 플랜에서는 Pages 를 쓸 수 없다(GitHub Pro 필요).
- 저장소를 **public** 으로 바꾸면 사이트도 공개된다 — 호가까지 공개된다.
- 호가를 빼고 올리려면 `.\sync_static.ps1 -NoQuotes`. 시장 분석만 남는데, 그쪽은
  전부 공개 데이터에서 나온 계수다.

`meta.json` 의 `includes_quotes` 로 그 스냅샷에 호가가 들어 있는지 확인할 수 있다.
