# 필요한 파일 찾기

**훑기 전에 범위부터 정한다.** 이 저장소는 '무엇을 하려는가' 로 길을 미리 깔아 두었다.
검색은 그 길이 끝난 데서 시작한다.

## 1. 길부터 탄다

1. **라우팅 표** — 루트 `CLAUDE.md` 의 '문서를 먼저 고른다' 표에서 하려는 일의 행을 찾아
   그 문서 **하나만** 연다. 자산 폴더(`backend/app/<자산>/`, `frontend/src/<자산>/`)에
   `CLAUDE.md` 가 있으면 그것도 연다.
2. **파일 지도** — [architecture.md](../../../docs/engineering/architecture.md) 의 배치도가
   파일마다 맡은 일을 한 줄로 적는다. 코드 위치는 여기서 고른다.
3. **자산 경계** — 자산 일은 그 자산 폴더 안에서 끝난다. `shared/`·`core/` 는 자산을
   모르고, 자산끼리는 서로 import 하지 않는다. 자산 폴더 밖이 걸리면 공통으로 뽑을
   때가 됐다는 신호다(뽑는 것은 실제로 두 번째로 쓰일 때).

여기서 고칠 파일과 그 파일을 다스리는 문서가 정해지면 2로 간다. 안 정해지면 3으로.

## 2. 이름을 쓰는 곳까지 모은다

바꾼 곳보다 **그 이름을 쓰는 곳**이 문제다. 아래 경계를 하나씩 건넌다.

- **엔드포인트** — 라우터 `APIRouter(prefix=…)` ↔ `frontend/src/api.js` ↔
  `backend/scripts/export_static.py` 의 `build_plan` ↔ 부르는 화면.
- **탭 id** — `App.jsx` 의 `TABS`(정적에 실리는지는 `static`) ↔ `realestate/topics/registry.js`.
- **코드 → 문서** — 코드 주석의 `docs/…` 경로와 `'절 제목'`. 문서 → 코드는 백틱 안의 이름·경로.
- **화면 문구** — 탭 이름을 바꾸면 조사까지 따라 바뀐다(받침).

이 경계는 `python -m scripts.verify_sync`(`backend/` 에서)가 대부분 잡는다. 이름을 바꿨으면
돌려서 남은 곳을 받는다 — 손으로 찾은 목록보다 이쪽이 완전하다.

## 3. 그래도 모르면 찾는다

- **Grep 도구**로 찾는다. `.claude/` 는 gitignore 라 Grep 도구는 남은 워크트리·옛 사본을
  건너뛴다. 셸에서 `grep -r` 을 쓰면 그 안까지 들어가 결과의 절반이 옛 코드가 된다.
- **Glob 은 자산 폴더로 좁힌다** — `backend/app/realestate/**/*.py`.
- **'왜 그렇게 됐나'** 는 코드가 아니라 기록에 있다 — `git log --oneline -- <경로>`,
  `git log -S '<이름>'`, 화면이면 [ui-log.md](../../../docs/screens/ui-log.md).
- **큰 파일은 위치를 잡고 그 부분만 읽는다** — `Grep -n` 으로 줄을 찾고 Read 의
  `offset`·`limit`. 길이는 그때 `wc -l` 로 잰다.

검색이 서너 번으로 안 끝나거나 이름 규칙을 모르면 **새 맥락의 Explore 서브에이전트**에
맡긴다. 프롬프트에는 찾을 것, 넓이(medium / very thorough), 그리고 **"결론만, `경로:줄`
로"** 를 적는다. 파일 내용을 받아 오게 하면 맥락만 차고 결론은 내가 다시 내야 한다.

## 끝났다는 기준

다음이 `경로:줄` 로 손에 있으면 탐색이 끝난 것이다.

- 고칠 파일 전부
- 그 이름을 쓰는 곳 전부(2의 경계를 다 건넜는지)
- 그 일을 다스리는 문서 하나, 그리고 함께 돌릴 검사(`verify_*`)
