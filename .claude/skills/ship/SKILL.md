# 마무리 — 검진 → PR → 머지 → 배포 확인

배포 구조는 [deploy.md](../../../docs/engineering/deploy.md) 에 있다. 여기는 순서와 끝난 기준만.

## 순서

1. **브랜치에서.** `main` 에 직접 커밋하지 않는다. 작업은 워크트리(`.claude/wt-*`)에서 한다 —
   본 체크아웃이 `main` 이 아니거나 더러우면 푸시 연동 배포가 '미룸' 으로 멈춘다.
   워크트리에는 `.venv` 가 없다. 본 체크아웃의 `backend/.venv/Scripts/python.exe` 로 돌린다.
2. **검진 전체** — `backend/` 에서 `python -m scripts.checkup`. `[X]` 는 고치고, `[!]` 는
   읽고 판단한다. 긴 출력은 스크래치패드 파일로 받는다.
3. **커밋** — 한국어. 제목은 무엇이 달라졌나 한 줄, 본문에 **왜** 와 **어떻게 확인했나**.
   성능·정확성 변경은 측정값을 적는다.
4. **PR** — `git push -u origin <브랜치>` 뒤 `gh pr create`. 본문에 변경 요지·확인한 것·
   안 한 것.
5. **CI 를 기다린다** — `gh pr checks <번호> --watch`(백그라운드로). 실패하면 로그를 읽고
   고쳐 다시 푸시한다. CI 는 DB 없이 되는 검진(`checkup --no-db`)과 프론트 빌드다.
6. **머지** — **그 브랜치의 워크트리에서** `gh pr merge <번호> --merge`(이 저장소는 머지
   커밋을 쓴다). 훅(`backend/scripts/merge_gate.py`)이 CI 통과와 그 워크트리의
   `checkup --fast` 를 확인하고, 아니면 막고 이유를 돌려준다 — 읽고 고친다. 그 뒤 본
   체크아웃을 `main` 으로 받아 둔다.
7. **배포 확인** — `main` 머지는 푸시 연동 배포가 10분 안에 올린다. 공개 사이트의
   스냅샷 `meta.json` 의 `git_head` 가 머지 커밋이 될 때까지 기다린다(백그라운드로).
   - 노트북이 **배터리**면 예약 작업이 시작하지 않는다(로그도 안 남는다). 전원을 알린다.
   - 손으로 올리는 것(`sync_static.ps1` 직접, `-AllowAnyBranch`)은 **사람에게 먼저 묻는다**.
8. **치운다** — 워크트리(`git worktree remove`)와 머지된 로컬 브랜치. 남기면 `grep -r` 가
   옛 지침서·옛 코드를 찾는다.

## 끝난 기준

- 공개 `meta.json` 의 `git_head` 가 머지 커밋이고, 바꾼 화면이 공개 사이트에서 열린다
- 워크트리가 치워졌다
- 사람에게 PR 링크와 확인한 것·못 한 것을 알렸다
