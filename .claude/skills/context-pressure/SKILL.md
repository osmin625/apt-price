# 맥락 압박 다루기

맥락은 **쓰는 만큼 줄고, 한 번 들어온 것은 빠지지 않는다.** 그래서 들이기 전에 고르고,
들인 것 중 오래 갈 것은 맥락 밖의 제자리로 옮긴다.

## 1. 들이기 전에 — 출력은 파일로, 맥락에는 요지만

- **긴 명령은 파일로 받는다.** `checkup`·`export_static`·적재 로그는 스크래치패드 파일로
  돌리고, 맥락에는 그 파일에서 고른 줄만 들인다 — 종료 코드, `[X]`·`[!]` 줄, 마지막 몇 줄.
- **세고 나서 본다.** 결과가 몇 줄일지 모르면 `wc -l`·`grep -c`·`git diff --stat` 로 먼저
  잰다. 많으면 `head` 나 패턴으로 좁힌다.
- **오래 걸리는 것은 백그라운드로** 돌리고 끝났다는 알림을 받아 결과 파일의 끝만 본다.
- **큰 파일은 부분만** — 위치를 Grep 으로 잡고 Read 의 `offset`·`limit`.

## 2. 넓게 읽어야 하면 — 새 맥락에 맡기고 결론만 받는다

읽기가 많은 일(코드 훑기, 외부 문서 조사, 같은 질문의 여러 갈래)은 **새 맥락의
서브에이전트**에 맡긴다. 주고받는 것은 **맥락 포인터**다 — 경로, `경로:줄`, 커밋, PR,
계획 파일. 내용을 붙여 넣어 넘기거나 받아 오지 않는다. 독립된 갈래는 한 번에 같이 띄운다.
파일 찾기는 [find-files](../find-files/SKILL.md) 의 3절.

## 3. 한 세션에 안 담기면 — 세션 크기로 자른다

- **한 PR = 한 세션 크기.** 앞 조각이 머지돼야 다음 조각이 기대는 순서로 자른다
  (예: 이동 → manifest → 문서·스킬 → 머지 관문 → 기능). 조각마다 검사로 닫고 머지한다.
- **결정이 남은 큰 일**은 바로 짓지 말고 결정부터 묻는다(grilling). 결정이 정해지면
  계획 파일에 적고, 그 파일이 다음 세션의 출발점이 된다.
- **제 결과물이 따로 있는 일**(다른 PR·다른 저장소)은 새 세션으로 넘긴다. 짧은 지시와
  포인터만 주면 되는 일이 그렇다.

## 4. 잃기 전에 — 오래 갈 것은 제자리로

맥락에서 알아낸 것은 세션이 끝나면 사라진다. 다음 사람이 다시 알아내야 할 것만 옮긴다.

| 알아낸 것 | 옮길 곳 |
|---|---|
| 데이터·모델·화면에 대한 새 사실 | 그 주제의 `docs/<묶음>/` 문서 (README 가 아니라) |
| 왜 그렇게 했는지, 무엇을 시도했다 버렸는지 | 코드 주석, 커밋 본문 |
| 사용자의 선호·작업 방식 | 메모리 (색인 줄도 같이) |
| 아직 안 한 일의 계획 | 계획 파일, PR 본문의 남은 일 |

## 5. 넘길 때 — 인수인계 문서

세션을 넘기거나 맥락이 거의 찼으면 인수인계 문서를 **스크래치패드**(저장소 밖)에 쓴다.

- **목표**와 지금 단계 — 계획 파일이 있으면 그 경로
- **끝난 것** — 커밋·PR 링크로 (내용을 다시 적지 않는다)
- **지금 상태** — 브랜치, 커밋 안 된 변경, 돌고 있는 백그라운드 작업
- **다음 할 일**과 그 끝났다는 기준
- **부를 스킬** — 다음 세션이 Skill 도구로 부를 것
- `backend/.env` 의 키, 개인 정보는 적지 않는다

## 6. 요약 뒤에 이어 갈 때 — 요약이 아니라 환경을 믿는다

요약(compaction)이나 인수인계 문서는 **그때의 기록**이다. 이어 가기 전에 지금을 다시 잰다 —
`git status`·`git branch --show-current`·`git log --oneline -5`, 열린 PR 상태, 백그라운드
작업이 끝났는지. 기록과 다르면 환경이 맞다.
